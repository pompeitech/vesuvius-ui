# Input

Un `<input>` nativo stilizzato — ogni tipo nativo (`text`, `email`, `password`, `number`, `file`, ...) condivide lo stesso trattamento visivo.

```tsx
import { Input } from "@pompeitech/vesuvius-ui";
```

<ComponentPreview code={`<Input type="email" placeholder="Email" />`}>
  <Input type="email" placeholder="Email" className="max-w-sm" />
</ComponentPreview>

## Dimensioni

## Input di tipo file

Il selettore nativo `type="file"` riceve lo stesso trattamento di bordo/focus degli input di testo, con il proprio pulsante stilizzato in coerenza:

<ComponentPreview code={`<Input type="file" />`}>
  <Input type="file" className="max-w-sm" />
</ComponentPreview>

## Stato non valido

Imposta `aria-invalid` — non esiste una prop separata `error`/`invalid`, così lo stesso attributo che usano gli screen reader guida anche lo stile:

<ComponentPreview
  code={`<Input aria-invalid placeholder="Email" defaultValue="not-an-email" />`}
>
  <Input
    aria-invalid
    placeholder="Email"
    defaultValue="not-an-email"
    className="max-w-sm"
  />
</ComponentPreview>

## API

**Input**

| Prop           | Tipo                                | Default     | Descrizione                                                                       |
| -------------- | ----------------------------------- | ----------- | --------------------------------------------------------------------------------- |
| `type`         | `React.HTMLInputTypeAttribute`      | `"text"`    | Qualsiasi tipo di input nativo.                                                   |
| `size`         | `"xs" \| "sm" \| "default" \| "lg"` | `"default"` | Altezza del controllo: 28, 32, 36 o 40 px.                                        |
| `aria-invalid` | `boolean`                           |             | Guida lo stile di stato non valido/errore — non esiste una prop `error` separata. |

Più ogni altra prop nativa di `<input>` (`disabled`, `placeholder`, `value`/`defaultValue`, `onChange`, `required`, `min`/`max`, `accept`, ...).

Comunemente abbinato a [`Label`](/docs/components/atoms/label) per la didascalia del campo e (in un contesto di form) a testo di aiuto/errore sotto di esso.

### Accessibilità

Associa sempre un `Input` a una `Label` tramite `htmlFor`/`id` corrispondenti (come sopra) invece di affidarti solo al `placeholder` — il testo placeholder scompare non appena l'utente inizia a scrivere e non è un nome accessibile affidabile per ogni tecnologia assistiva.
